Why Do We Need a Kalman Filter? — A Drone Story

Imagine a drone flying from one place to another.

The drone has three sources of information:

  1. a mathematical model of motion,
  2. a sensor (GPS/IMU),
  3. and the real world, which is never perfect.

The easiest way to think about Kalman filtering is to think like the drone.

Step 1: The drone starts with physics

Suppose the drone knows its current position and velocity. Using Newton’s laws, it predicts where it should be after the next time step.

If nothing disturbed the drone, the predicted path would look smooth and clean. This prediction is called the Mathematical Model.

In our plots it is the black dashed curve.

If the world were perfect, I would fly along this path.

Step 2: The real world interferes

Now imagine wind gusts, vibration, sudden jerks, motor mismatch, air turbulence, or payload changes. These effects push the drone away from the ideal path.

So the drone’s actual trajectory becomes slightly different from the mathematical prediction. This actual path is called the Ground Truth.

In our plots it is the blue curve.

The blue curve represents what the drone is really doing in the world.

The Kalman filter does not know this blue curve during operation. In simulation we know it only because we created the experiment ourselves.

Step 3: The sensor tries to observe the drone

The drone has a GPS or IMU. Sensors are not perfect. Temperature, electrical noise, vibration, multipath effects, and many environmental factors make the readings fluctuate.

So the sensor reports a noisy measurement. This is the Sensor Measurement.

In our plots it is the green curve or green dots.

The green signal is what the drone can actually read from its hardware.

Step 4: What information does the drone really have?

At each instant the drone knows:

  • the black model prediction,
  • and the green sensor reading.

It does not know the blue ground truth.

So the drone asks:

The model says one thing.
The sensor says another thing.
Which one should I trust more?

This question is exactly what the Kalman filter answers.

Step 5: How Kalman Answer?

Suppose the mathematical model predicts that the drone should be at a certain position. In reality, wind, vibration, motor mismatch, and many other effects can push the drone away from that ideal path.

Therefore, we do not expect the drone to be exactly on the mathematical-model curve. Instead, we expect it to be somewhere around that curve.

The model gives the most likely position, while Q describes how uncertain we are about that prediction.

For intuition, we often imagine that the possible deviation is Gaussian:

Q ~ N(μq, σq2)

  • μq → average deviation from the model (often assumed 0),
  • σq → spread of possible deviations.

This means the true drone position is expected to lie around the mathematical-model prediction, and roughly 68% of the probability mass lies within (prediction + μq) ± 1σq.

A larger σq means a wider possible range of motion, so the model is trusted less.

Sensor uncertainty

The sensor reading is also not exact. GPS, IMU, and other sensors contain measurement noise.

We represent this uncertainty by R and again imagine a Gaussian distribution:

R ~ N(μr, σr2)

  • μr → average sensor bias (often assumed 0),
  • σr → spread of sensor readings.

Roughly 68% of the probability mass lies within (sensor mean + μr) ± 1σr.

A larger σr means the sensor is less reliable.

Visual meaning

Think of tree bell curves (Uncertainty (Gaussian Beliefs)):

  • Model belief (Black curve) centered at the mathematical prediction with width σq.
  • Sensor belief (Green curve) centered at the sensor measurement with width σr.

The Kalman filter combines these two beliefs and produces a new bell curve (the Kalman estimate (Red curve)) whose center is usually between the model prediction and the sensor measurement.

In normal situations, the fused uncertainty is usually smaller than either individual uncertainty, so the final estimate is typically more confident than using only the model or only the sensor.

The important idea is not that we add a "dummy noise signal" to the model. Instead, we say:

  • "The true state is probably near the model prediction with uncertainty Q."
  • "The true state is probably near the sensor measurement with uncertainty R."

The Kalman filter mathematically combines these two beliefs to obtain the best estimate of the unknown true drone position.

What the Kalman Filter Computes Internally

The filter runs a repeated predict → compare → correct cycle.

1. Prediction from the mathematical model

x̂k|k−1 = A x̂k−1|k−1 + B uk

This is the predicted state before seeing the new sensor measurement.

The prediction uncertainty is

Pk|k−1 = A Pk−1|k−1 Aᵀ + Q

Larger Q increases the prediction uncertainty.

2. Sensor measurement arrives

zk = C xtrue + vk

The sensor provides a noisy observation of the true state.

3. Innovation (measurement residual)

rk = zk − C x̂k|k−1

This tells us how much the sensor disagrees with the model prediction.

4. Kalman gain

Kk = Pk|k−1 Cᵀ ( C Pk|k−1 Cᵀ + R )⁻¹

  • large Q → trust the sensor more,
  • large R → trust the sensor less.

5. State update

x̂k|k = x̂k|k−1 + Kk rk

The prediction is corrected using the innovation.

6. Covariance update

Pk|k = ( I − Kk C ) Pk|k−1

After using the measurement, the uncertainty is usually reduced.

One Complete Cycle

Previous estimate 
    x̂(k−1|k−1)
        ↓
Prediction using model 
     x̂(k|k−1)
        ↓
Receive sensor measurement z(k)
        ↓
Compute innovation r(k)
        ↓
Compute Kalman gain K(k)
        ↓
Correct the prediction 
      x̂(k|k)
        ↓
Update uncertainty P(k|k)
        ↓
Repeat for the next time step

This is the complete intuition and mathematical cycle behind the Kalman filter.

Numerical Example: Two Complete Kalman-Filter Iterations

This example shows how a Kalman filter starts from an initial guess and then improves its estimate step by step. We will perform two full iterations so that the role of the covariance matrix becomes clear.

System model

State vector:

x = [ position ; velocity ]

Sampling time: Δt = 1 s

State-space matrices:

A = [[1,1],[0,1]]

B = [[0.5],[1]]

The sensor measures both position and velocity:

C = I = [[1,0],[0,1]]

Process uncertainty:

Q = [[0.5,0],[0,0.2]]

Measurement uncertainty:

R = [[1,0],[0,1]]

Initialization (before iteration 1)

Initial state estimate:

x̂(0|0) = [0 ; 10]

Initial uncertainty:

P(0|0) = [[1,0],[0,1]]

This means we initially believe:

  • position ≈ 0 m,
  • velocity ≈ 10 m/s,
  • uncertainty is 1 unit in each state.

Iteration 1

Control input

u(1) = 2 m/s²

Prediction

x̂(1|0) = A x̂(0|0) + B u(1)

x̂(1|0) = [11 ; 12]

Predict uncertainty

P(1|0) = A P(0|0) Aᵀ + Q

First:

A P Aᵀ = [[2,1],[1,1]]

Add Q:

P(1|0) = [[2.5,1],[1,1.2]]

Sensor measurement

z(1) = [10.2 ; 11.5]

Innovation

r(1) = z(1) − x̂(1|0)

r(1) = [−0.8 ; −0.5]

Kalman gain

K(1) = P(1|0) (P(1|0)+R)⁻¹

K(1) ≈ [[0.677,0.151],[0.151,0.481]]

Update state

x̂(1|1) = x̂(1|0) + K(1) r(1)

x̂(1|1) ≈ [10.383 ; 11.638]

Update uncertainty

P(1|1) = (I − K(1)) P(1|0)

P(1|1) ≈ [[0.677,0.151],[0.151,0.481]]

After using the measurement, the uncertainty became much smaller than the prediction uncertainty. The filter is now more confident.

Iteration 2

Now we use the updated estimate and covariance from iteration 1.

New control input

u(2) = 1 m/s²

Prediction

x̂(2|1) = A x̂(1|1) + B u(2)

Compute:

x̂(2|1) ≈ [22.521 ; 12.638]

Predict uncertainty

P(2|1) = A P(1|1) Aᵀ + Q

P(2|1) ≈ [[1.960,0.632],[0.632,0.681]]

Notice that uncertainty increased again because of the process uncertainty Q.

New sensor measurement

z(2) = [22.0 ; 12.1]

Innovation

r(2) = z(2) − x̂(2|1)

r(2) ≈ [−0.521 ; −0.538]

Kalman gain

K(2) ≈ [[0.631,0.080],[0.080,0.391]]

Update state

x̂(2|2) = x̂(2|1) + K(2) r(2)

x̂(2|2) ≈ [22.149 ; 12.386]

Update uncertainty

P(2|2) ≈ [[0.631,0.080],[0.080,0.391]]

What did we learn?

Step Position (m) Velocity (m/s)
Initial estimate 0.000 10.000
Prediction 1 11.000 12.000
Update 1 10.383 11.638
Prediction 2 22.521 12.638
Update 2 22.149 12.386
This table shows the real behavior of a Kalman filter:
  • Prediction moves the state forward using physics.
  • Measurement pulls the estimate toward the sensor.
  • Q increases uncertainty during prediction.
  • R controls how strongly the sensor influences the estimate.
  • The updated covariance is reused in the next iteration.
This is exactly how a Kalman filter runs continuously in real systems such as drones, robots, autonomous vehicles, and navigation systems.

The intuition behind Q and R

Model belief

  • Center = model prediction
  • Width = uncertainty in physics

This uncertainty is represented by Q.

Large Q means:

I do not trust my model much.

Small Q means:

My physics model is probably accurate.

Sensor belief

  • Center = sensor reading
  • Width = uncertainty in measurement

This uncertainty is represented by R.

Large R means:

The sensor is noisy.

Small R means:

The sensor is reliable.

What the Kalman filter actually does

The filter combines these two beliefs.

  • If the sensor is very noisy, the estimate stays closer to the model.
  • If the model is very uncertain, the estimate stays closer to the sensor.
  • If both are reasonably reliable, the estimate lies somewhere in between.

The result is the Kalman Estimate. In our plots it is the red curve.

The red curve is the filter’s best guess of the true drone motion.

Reading the four curves on the graph

Curve Meaning
Black dashed Ideal mathematical prediction
Blue Actual drone motion (ground truth)
Green Noisy sensor reading
Red Kalman fused estimate

When you look at the graph, think:

  • Black → What physics expected.
  • Blue → What actually happened.
  • Green → What the sensor reported.
  • Red → What the filter believes.

What happens when Q changes?

Small Q

  • The filter trusts the model.
  • Red stays near black.
  • Motion looks smooth.
  • Sudden disturbances are followed slowly.

Large Q

  • The filter trusts the sensor more.
  • Red moves toward green.
  • Tracking becomes faster.
  • The estimate may become noisier.

What happens when R changes?

Small R

  • Sensor is trusted.
  • Red follows green closely.

Large R

  • Sensor is distrusted.
  • Red ignores much of the sensor noise.
  • Red stays closer to black.

Notice that changing R does not change the real drone motion; it only changes how much the filter trusts the sensor.

The complete mental picture

Think of the drone continuously repeating this loop:

Physics model predicts
        ↓
Sensor measures
        ↓
Kalman filter compares both
        ↓
Best estimate is produced
        ↓
Use that estimate for navigation and control

The goal of the Kalman filter is not to reproduce the mathematical model and not to reproduce the noisy sensor.

Its goal is to recover the hidden blue trajectory—the closest possible estimate of the real motion.

Once this story is clear, the state-space equations and Kalman mathematics become much easier to understand, because every symbol corresponds to a physical object in the story.
